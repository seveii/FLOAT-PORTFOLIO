2 · Float: the nav and the main page columns

The site uses three layout methods. Float is the oldest, so it's worth being able to explain from first principles, not just point at the code. It drives the nav pill, the two-column About and Skills layouts, the home page's About card and credentials row, the section headings with a button on the right, and the drop cap. Flexbox and Grid are covered in the sections after this one.

What float actually does

Normally every block element stacks top to bottom, full width. float: left or float: right pulls an element out of that normal stacking and pushes it to one side, letting whatever comes after it flow up alongside it instead of underneath it. That "letting content flow beside it" behavior is the entire mechanism — it's literally how magazine layouts wrapped text around a photo before CSS existed. Two elements floated left and right at fixed widths sit side by side, which is how every multi-column section on this site is built.

about.html — the two-column bio layout
.about-text{ float:left; width:58%; } .about-photo{ float:right; width:36%; }

No flex or grid container is needed for this — the two elements just claim opposite sides of their container.

The problem float creates: collapsing height

A floated element is taken out of normal flow, so its parent no longer "sees" its height. If every child of a container is floated, the parent collapses to zero height — borders and backgrounds on that parent visually disappear, because as far as the parent's box model is concerned, it has no content in it.

Without a clearfix

The nav's background pill and border would collapse to a sliver, because every child inside it — the logo, the links, the button — is floated.

With a clearfix

A tiny generated element after the floats forces the parent to expand and wrap around them properly.

css/style.css — the clearfix used on every floated container
.floatnav-inner::after{ content:''; display:table; clear:both; }

This pattern — an empty ::after pseudo-element set to clear: both — is called a clearfix. It's the standard fix for the float-collapse problem, and it's why you'll see ::after{ content:''; display:table; clear:both; } repeated after every floated container in the stylesheet: .floatnav-inner, .about-grid, .skills-grid, .section-head-row, and so on.

Why float is not used for the card grids

Floated cards don't stretch to match each other's height, and a row of cards has to be hand-tuned with percentage widths and :nth-child margin resets. That's the job CSS Grid was built for, so every grid of cards uses Grid instead (section 4).

The thing float can't do: vertical centering

Float only controls left/right position — it has no concept of centering something vertically the way align-items: center does in Flexbox. The nav bar needed its logo, links, and button to look vertically centered in a pill-shaped bar, so instead of Flexbox, it uses a much older trick: set every item's line-height equal to the bar's total height, which centers single-line text automatically.

css/style.css — line-height as a centering trick
.floatnav-inner{ min-height:3.6rem; } .logo{ float:left; line-height:3.6rem; } /* line-height = bar height → text centers itself */ .navlinks li{ float:left; line-height:3.6rem; margin-right:2.1rem; }

Good follow-up if asked: "Why not use align-items: center?" — the nav is deliberately the float showcase, so it uses the line-height trick. Flexbox's align-items: center is used elsewhere, such as inside the buttons.

3 · Flexbox: rows of small things

Flexbox lays items out along one line and handles spacing, alignment and wrapping for you. It's used wherever there's a row of small items:

  • Buttons — display:inline-flex; align-items:center; gap:.5em centers the label and arrow and spaces them evenly.
  • Tag and chip rows — display:flex; flex-wrap:wrap; gap:.7rem lets chips wrap onto new lines automatically.
  • The footer — justify-content:space-between puts the logo on one side and the links on the other, and flex-wrap stacks them on small screens.
  • The stat strip — each box is flex:1 1 180px, so four across on desktop, two on a tablet, one on a phone, with no media query.
css/style.css — the wrapping tag row
.tagrow{ display:flex; flex-wrap:wrap; gap:.7rem; }

4 · CSS Grid: the cards

Grid lays items out in rows and columns at once. Every grid of cards uses it: the project cards, both photo galleries, the credentials cards and the home page summaries. Because grid cells in a row share a height, cards line up without any hacks.

css/style.css — the project cards
.work-grid{ display:grid; gap:2.5rem 3rem; grid-template-columns:repeat(auto-fit, minmax(min(100%,360px), 1fr)); }

Read it as: "make as many columns as fit, each at least 360px wide, and share the leftover space equally." On a wide screen that's two columns. On a phone it's one. No media query is needed.

5 · Positioning: the bits the three methods don't cover

Some things aren't about rows or columns at all, like pinning text to the bottom of a photo or overlaying a panel on the page.

The project lightbox (full-screen overlay)

works.html opens a full case-study panel with no JavaScript, using the CSS :target selector — the browser adds an :target match to whatever element's id matches the current URL's #hash, so a plain link like <a href="#project-1"> can open it. The panel itself is position: fixed to cover the screen, and it scrolls inside itself when a case study is taller than the screen:

css/style.css — a full-screen overlay that scrolls
.lightbox{ position:fixed; inset:0; z-index:500; overflow-y:auto; /* long case studies scroll instead of clipping */ opacity:0; pointer-events:none; /* hidden until :target matches */ } .lightbox:target{ opacity:1; pointer-events:auto; }

The key idea: inset:0 stretches the fixed panel to all four edges of the screen. The :target rule fades it in when the URL hash matches its id. pointer-events:none while hidden means it never blocks clicks on the page underneath.

Pinning the hero text to the bottom of the photo

index.html — the cover page's text block
.hero-content{ position:absolute; left:0; right:0; bottom:0; }

Same idea, simpler: left:0; right:0 stretches it full-width, bottom:0 pins it to the floor of the hero section — no float needed because nothing sits beside it to push against.

6 · Other techniques worth naming

  • CSS custom properties — every color, radius, and easing curve is a variable in :root (--accent, --surface, --ease…), so the whole site's palette can change from one place.
  • :target for the lightbox — no JavaScript modal library; a hidden panel becomes visible purely because its id matches the URL hash.
  • The mobile menu is a checkbox, not JS — a hidden <input type="checkbox"> plus a <label> styled as a hamburger icon. CSS reads #nav-toggle:checked ~ .navlinks to slide the menu in — a real click/state toggle with zero script.
  • CSS keyframe animation — the fade-up entrance on each section and the scroll cue on the cover page are @keyframes, not JS.
  • Media queries and fluid sizing — at 980px the nav links collapse into the slide-in menu, at 860px the float columns stack (float:none; width:auto;), and at 560px the gutters tighten. Grids adapt on their own with auto-fit/minmax(), and spacing scales with clamp().

7 · Likely questions, ready answers

Why did you use float, Flexbox and Grid together?

Each one is used where it fits best. Float handles the nav bar and the main two-column page layouts, and it needs a clearfix so the parent wraps its floated children. Flexbox lays out a single row of small items, like buttons, tags and the footer. Grid lays out rows and columns together, so every grid of cards uses it.

Using all three shows I understand what each is for, and where one is a better tool than another. For example, floated cards can not stretch to equal heights, but grid cards can.

What's the actual difference between float:left and float:right?

float: left pulls the element to the left edge of its container and lets later content wrap along its right side. float: right does the mirror image — pulls to the right edge, content wraps along its left. Order in the HTML doesn't decide which side an element ends up on; the float value does.

What happens if you forget to clear a float?

The parent container collapses — since it no longer "contains" any in-flow content — so its background, border, and padding effectively disappear, and anything after it in the HTML flows up underneath the floated elements instead of below them. That's why this project adds a ::after{ clear:both; } clearfix on every container that has floated children.

How do the card grids stay responsive without media queries?

The grid container uses repeat(auto-fit, minmax(min(100%, 360px), 1fr)). That means "as many columns as fit, each at least 360px wide". The browser works out the column count itself, so there is nothing to switch at a breakpoint.

Doesn't float break on mobile?

It would if left alone, because fixed percentage widths leave no room to stack on a narrow screen. A media query at 860px resets the floated columns back to float: none; width: auto;, so on phones they stack one per row. The nav collapses into a slide-in menu at 980px, where the links would otherwise run out of room.

How does the image lightbox open without any JavaScript?

It uses the CSS :target pseudo-class. Each lightbox is a hidden full-screen <div id="project-1"> with opacity:0; pointer-events:none. A project card links to #project-1. When that's the current URL hash, the browser matches #project-1:target in the CSS, which flips it to opacity:1; pointer-events:auto. The browser does the state-tracking; no script is involved.

Why does the nav bar look centered if float can't center things?

It's not actually centered by float — float only pushes left/right. The vertical centering comes from a different, older trick: every nav item's line-height is set equal to the bar's height, which centers a single line of text inside its own box automatically. Combined with float for the left/right placement, the two techniques together produce what looks like a normal centered nav bar.

8 · Quick glossary

float
A CSS property that removes an element from normal block flow and pushes it to the left or right edge of its container, letting other content wrap alongside it.
clear
Forces an element to move below any floated elements before it, instead of wrapping beside them.
clearfix
The standard workaround for a parent collapsing around floated children — an empty ::after pseudo-element set to clear: both.
normal flow
The default way block elements stack — top to bottom, full container width — before any float or positioning changes it.
:target
A CSS pseudo-class that matches an element whose id equals the current URL's #hash — what makes the JS-free lightbox possible.
